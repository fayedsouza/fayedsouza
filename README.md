## Faye D'Souza

Senior technical writer, 16 years. I work on documentation systems — the structure, the standards and the publishing pipeline — as well as the content that goes in them.

### What I work on

- **Structured authoring** — DITA/XML topic architecture in Oxygen XML Author, single-sourced across product versions and across cloud and on-premise deployments. Planned and delivered the migration of a full documentation estate into a CCMS.
- **Docs-as-code** — Markdown in Git, static site generation, validation at build time, CI/CD publishing.
- **Documentation standards** — founded a peer-review and QA programme: style, terminology, information architecture, and the review process that holds them in place.
- **AI-augmented documentation** — a validated prompt library for drafting and editing, and an LLM and RAG evaluation establishing where generated answers could be trusted and, more usefully, where they could not.

### tessera-docs

[**tessera-docs**](https://github.com/fayedsouza/tessera-docs) — a documentation site built as docs-as-code, published at [fayedsouza.github.io/tessera-docs](https://fayedsouza.github.io/tessera-docs/).

Markdown in Git, MkDocs Material, deployed by GitHub Actions. The build runs in strict mode, so a broken internal link fails the build rather than reaching a reader. The commit history includes a deliberate CI failure and the fix for it — the pipeline is as much the point as the pages.
